# ザクロの継承

4〜8人で遊ぶ、袋の秘密操作と略奪のオンラインボードゲーム。部屋コード／招待リンクで参加し、それぞれのブラウザーに本人が見られる情報だけを表示します。

## 手元で起動

Node.js 22以降をインストールし、このフォルダーで `npm start` を実行して http://localhost:3000 を開きます。追加パッケージのインストールは不要です。

各自のPC・スマホから遊ぶ場合は下記のRailway公開URLを使用します。localhostのURLは友人には共有できません。

## GitHub → Railwayで公開

1. GitHubで空のリポジトリ `zakuro-succession` を作成します。ソースを一般公開する必要はありません（Private可）。
2. このフォルダーをそのリポジトリへpushします。既存のDixitとは別リポジトリ・別サービスにしてください。
3. Railwayで **New Project → Deploy from GitHub repo** を選択し、新しいリポジトリを指定します。ルートのDockerfileで起動します。
4. データを再起動・再デプロイ後も残すため、サービスにVolumeを追加し、マウント先を `/data` に設定します。環境変数 `DATA_DIR=/data` を追加してください。
5. サービスのレプリカ数は **1** にします。複数レプリカには対応していません。
6. Networkingで公開ドメインを生成します。アプリはRailwayの `PORT` に待ち受けます。
7. 公開URLで4人が参加し、部屋作成→開始→選択→銃撃→結果を確認します。その後はGitHubへのpushで更新できます。

公式資料：[GitHub連携とDockerfile](https://docs.railway.com/services)、[Volume](https://docs.railway.com/volumes)。料金はRailway側の契約・利用量によります。

Volumeなしでも起動しますが、デプロイをまたぐ対戦データの保存は保証できません。

## 遊び方

- 継承順位を1〜参加人数でランダムに割り当て、常時公開します。第1セットは1位から。
- 全3セット。袋は最初の参加人数をNとして、1・2セット目はN+1個、3セット目は2N+2個。指輪が袋にある場合は個数に含みます。役職の初期所持品は別です。
- 各セット開始時に袋の構成を全員に公開。各自が確認すると袋を回します。
- 第1セットは1個取得、第2セットは1個取得＋任意で1個交換、第3セットは2個取得＋任意で1個交換。交換で戻せるのは手番開始前から持っていた品物です。
- 袋の現在の中身は手番の本人だけ、所持品と秘密ボーナスは本人だけに表示。指輪の持ち主は全員に公開。
- 袋を回した後、同じ順で各セット1回ずつ銃撃するか見送ります。銃＋弾薬が必要。銃は残り弾薬は1個消費。人形1個で1発防ぎ、人形は消費。防げないと死亡し、その人の全所持品を射手が奪います。死亡者の以後の手番は飛ばします。
- 指輪は全体で唯一の1個。初回の袋に必ず入り、袋に残れば次回に引き継ぎます。持ち主はセット開始時に先頭を指名します。以降は番号順で一周。持ち主がいなければ前回と同じ先頭（死亡時は次の生存番号）です。
- 1人生存で即勝利。第3セット後は生存者の「本物の宝石＋ボーナス達成1点＋指輪1点」を比較。同点は指輪所持→ボーナス達成→番号が小さい順。
- 偽物は初期所持者には分かります。袋へ戻した後は真贋を表示しません。偽銃は破棄して弾薬は残るが手番終了。偽弾薬は消費して不発。偽人形は銃撃時に破棄、本物もあれば本物1個で防ぎます。偽宝石は最終採点で0点。

## 初版で採用した調整可能な設定

ユーザーと確定した基本ルールに加え、次は初版の実装上の選択です。

- 公開役職9種類を重複なしで配布。宝石・銃・弾薬・人形を1個持つ4種、各偽物を1個持つ4種、情報屋1種。指輪初期所持の役職は未採用。
- 秘密ボーナスは役職と独立に配布し重複あり。復讐（自分以外で継承順位最上位を自分で倒す）、平和主義（死亡ゼロで終了）、頑強（2発以上防いで生存）。各1点。
- 情報屋は1ゲーム1回、指定した他人がそのセットに袋から取った種類を確認できます。交換で戻した種類・真贋は分かりません。
- 袋には宝石・銃・弾薬・人形を各1個保証し、残りは宝石が一定割合になるよう補充してからランダムに構成します。4人の第1セットは指輪を含む5種類1個ずつとなります。
- 初期所持した偽物も一旦袋へ戻せば識別できなくなります。略奪した偽物も真贋は分かりません。
- 次セットはホストが開始し、初期袋の確認は生存者全員の準備完了を待ちます。

## 接続と運用

- 同じタブの再読み込み・一時的な通信断は自動復帰。本人用の参加トークンはそのタブのsessionStorageに保存します。URLにトークンは含みません。
- ロビー退出は席を削除。対戦中の退出は席を残しており、同じタブで戻れます。長時間離席すると対戦はその手番で待機します。
- **タブを完全に閉じて参加情報が失われた場合、別端末・別ブラウザーから本人の席へ復旧する機能はありません。** 初版では途中参加、途中の代理操作、タイムアウト脱落、音声通話を実装していません。
- 対戦データには秘密情報が含まれます。`data/` はGitから除外しています。サーバー管理者は保存データを参照できるため、一般向けの不正対策が必要な競技サービス向けではありません。
- 対戦状態は操作ごとに保存。7日間更新がなく接続もない部屋は自動削除。最大200部屋。
- 健全性確認：`GET /health`。Node標準HTTP＋SSEで状態同期。フロントはHTML/CSS/JavaScriptです。

## 検証

`npm test`：ルール、情報の秘匿、4〜8人の全セット進行、リアルタイム同期、古い操作の拒否、再接続、サーバー再起動後の復元を検証。

`npm run check`：JavaScriptの構文を確認。

ルールは `lib/game.mjs`、通信・保存は `server.mjs`、画面は `public/` にあります。
